- Cards whose 17Lands win rate is withheld for a thin sample stay in set
  profiles with their ALSA. Profile generation used to drop them, so cards
  such as TRK's Combadge showed as a bare DO 50. A profile card with no games
  in hand now uses the neutral prior adjusted by its ALSA and shows no win
  rate, and the "close pick" banner no longer fires when either of the top
  two cards has no win rate. (#1076)
- TRK basic lands no longer show as "Unknown card" in live drafts. The TRK
  card data had no basic lands, because neither Scryfall nor 17Lands lists
  their Arena ids. `scripts/patch_scryfall_arena_ids.py` has a new
  `--basic-lands` option that derives them from the collector-number offset
  every TRK card shares, and the TRK card data now holds the 20 Arena basics.
  (#1075)
- The deck builder can splash again in the app. The splash check read card
  win rates only from 17Lands data, which the app no longer loads, so no
  splash colour was ever set. It now uses the set profile's win rates when
  17Lands data is missing, and ignores profile ratings with no games in hand.
- Add Star Trek (TRK) card data and early Premier, Traditional and Pick-Two
  profiles. Scryfall has no Arena ids for TRK yet, so this one-time export
  takes the 336 Arena ids from 17Lands ratings, as was done for FRA.
- Card name matching between 17Lands and Scryfall now ignores spaces and case.
  17Lands writes "All Good Things . . ." and Scryfall writes "All Good
  Things...", so the TRK export failed on that card.
- Fix TUI backtest tests that failed at random on a busy machine, because they
  checked the result one frame after starting a command on a worker thread.
- CI now builds the website on every run. Dependabot pull requests with patch
  or minor updates merge automatically once all CI jobs pass, and CI then runs
  on `master`. Major and unknown updates stay open for review.
- The scheduled data refresh no longer pushes generated website data to
  `master` untested, and a successful refresh no longer opens a pull request.
  The publisher dispatches CI on the data branch and waits up to 20 minutes.
  It pushes to `master` only after CI passes on that exact commit, then deletes
  the branch. If CI fails or times out, `master` stays unchanged and the branch
  stays for inspection. A partial refresh still opens a pull request, and CI is
  dispatched on its branch too. The `CI` workflow can now be started by hand,
  and it runs on every pull request, including data-only ones.
- The native bundle build now passes `--no-install` to `pyside6-deploy`. PySide6
  6.12 runs `pip freeze` during deployment, and the uv environment has no `pip`,
  so every macOS and Windows bundle build failed.
